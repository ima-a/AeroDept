# Exploratory KD with the rejected teacher

This separate entry point requires an explicit, hashed authorization bundle. It does not change `expanded_training.py`, `expanded_sequence.py`, the original quality gate or historical source hashes. The original gated full KD constructor still rejects the selected teacher B. This is exploration with a rejected teacher, and must not be reported as the accepted-teacher arm of the original study.

`exploratory_kd.py` validates the original A/B completion receipts, selected checkpoint hashes, original failed gate, parent sources and matched student controls. It uses a distinct checkpoint arm/scope and pins the exploratory source, authorization, original initialization, baseline, rejected gate and dataset root. Its parent constructor receives this explicit exploratory scope only after these checks; it never pretends the gate passed or changes the original full KD scope. Checkpoints cannot be interchanged with gated KD or original A/B. Runtime configuration keeps the existing `arm: kd` recipe with an additional explicit exploratory arm field; checkpoint identity uses `exploratory_kd_rejected_teacher_v1`.

The existing training step, KD/supervised loss, AMP recovery, loader, FP32 validation and atomic checkpoint serialization are reused unchanged. The new epoch loop is syntax-tree checked against the original epoch loop, apart from additional progress reporting. Both student arms independently start from the original epoch-4 state including BN buffers, with fresh optimizer/scaler/scheduler/RNG/history and seed42. The teacher is official selected B best, FP32/eval/no-grad, using the same augmented RGB. There is no teacher repair, extra near/selective loss, schedule change, coefficient search, early stopping or deployment promotion.

One frozen launch bundle on the user-selected AERODEPTH rescue USB contains `authorization.json`, original input copies, source/configuration, `freeze.json`, service start/stop/manual-resume scripts, logs and its own `run/` directory. Original HDD paths inside historical receipts are preserved; only the in-memory baseline-path field is normalized when checking the identical rejected gate against byte-identical recovered checkpoints. No new accepted gate is created.

Best/last/previous-best are epoch-boundary atomic checkpoints; retain them together. Manual resume accepts only this run's own complete last boundary and strict identity, including source and rejected gate. An unfinished epoch replays. Before the first completed epoch, no resumable last checkpoint exists. No automatic whole-run retry or additional arm is launched.

Use the dated launch handoff under `results/` for exact bundle/service paths. User-level sleep/lid inhibitors do not establish physical lid behavior or prevent forced shutdown, USB removal or full logout (`Linger=no`). Keep AC connected, the lid open and the USB mounted. All outcomes, including negative validation results, remain exploratory evidence. Reserved test RGB/depth remains inaccessible through the manifest guard.
